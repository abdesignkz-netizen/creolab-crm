Основание — A1 в `BASQAR_AI_OS_AUDIT.md`. Изменения выполнены поверх A0 в текущем каталоге и ветке `codex/stage9-release`, исходный HEAD `85ca15135f64ce2f7d54b129da8c3703001cae7d`. ## Пользовательский результат

В **BasQar Control → Планы действий** сотрудник с правом управления задачами может:

1. Создать новую задачу или найти существующую по названию.
2. Выбрать сотрудника, клиента, срок и описание новой задачи.
3. Сохранить подготовленный текст как черновик ответа в задаче.
4. Добавить уведомление конкретному сотруднику внутри BasQar.
5. Посмотреть точный состав изменений и подтвердить весь план.
6. Увидеть результат каждого шага, открыть задачу, остановить оставшиеся действия.

Один план относится к одной задаче и содержит до пяти шагов. Повторное создание плана с тем же ключом возвращает существующий план. История показывает статус и число выполненных шагов; полные тексты загружаются при открытии. В предварительном просмотре явно указана замена существующего черновика. При переходе к просмотру фокус и прокрутка переводятся к заголовку плана.

Если часть плана не выполнена, ранее завершённые действия сохраняются. Есть переход к подготовке оставшихся действий для уже созданной задачи. Все оставшиеся действия проходят новый просмотр и подтверждение; автоматического повтора всего плана нет.

## Что реализовано

| Область | Реализация |
|---|---|
| Контракты | `aiAction.ts`: строгие схемы четырёх действий, запросы подтверждения/отмены, состояния плана/шага, результат и краткая история. Запрещены неизвестные поля, циклы/ссылки вперёд и несколько задач в одном плане. |
| Реестр | `aiActionRegistry.ts`: `task.create`, `task.assign`, `task.draft`, `staff.notify`; проверка прав, задачи, сотрудника и фактического результата. |
| Данные | `ActionRun` и `ActionStep`: компания, инициатор, ключ запроса, неизменяемый состав, хеши исходных данных, лимиты, ссылки на подтверждение/очередь/задачу, результат шага. Составной внешний ключ не позволяет привязать шаг к плану другой компании. Исторические ссылки сохраняются отдельно от операционных записей. |
| Подтверждение | Использует `ControlConfirmation` с отдельным источником `AI_ACTION_PLAN`. Показанный `planHash` обязателен. Подтверждение и постановка одного события в очередь сохраняются вместе. |
| Исполнение | Существующие `createTask`, `assignTask`, сервис черновиков и уведомлений. Изменение, проверка результата, запись шага и аудит сохраняются в одной транзакции. Проверки после изменения могут откатить только текущий шаг через savepoint. |
| Очередь | `ai.action_run` в существующем outbox. Перезапуск продолжает только невыполненные шаги. Исчерпание попыток становится видимым прекращением плана, а не бесконечным ожиданием. |
| История | Сохраняются подготовка, подтверждение, каждый выполненный шаг, остановка, отмена и итог. Созданные через Control задачи используют существующую запись истории задачи/клиента. |
| API | GET/POST `/api/v1/workspace/ai-actions`, GET `/options`, GET `/:id`, POST `/:id/confirm`, POST `/:id/cancel`. Старые task/Control endpoints остаются. |
| UI | Отложенно загружаемый раздел `/control?view=plans`, форма, поиск, предварительный просмотр, автоматическое обновление выполняемого плана, история, отмена и переходы к задаче. |
| Миграция | Аддитивный `AI_ACTION_SQL` подключён к PostgreSQL и PGlite. Старая история не переносится и не запускается заново. |

## Ограничения исполнения

- Действует доступ текущего сотрудника к CRM_CHAT в Control и возможности тарифа AI_CONTROL/TASKS. Права владельца автоматически не выдаются. Администратор платформы в режиме настройки чужой компании не становится её сотрудником.
- Перед каждым шагом заново проверяются действующий пользователь, участие в компании, права Control, тариф, пауза ИИ, сотрудник и исходное состояние задачи. Изменение данных требует нового плана.
- Подтверждение доступно 30 минут. На выполнение после подтверждения отведены ещё 30 минут. Не больше 20 неистёкших активных планов на инициатора; не больше пяти шагов и одной задачи в плане.
- Текущий атомарный шаг может завершиться перед отменой. Следующие шаги после сохранённой отмены не выполняются. Уже завершённые действия не откатываются.
- Прямой отправки клиентам, выставления/подтверждения платежей, удаления, смены ролей или произвольных инструментов в реестре нет. Сохранение черновика не подтверждает и не планирует отправку.
- Нельзя изменить через новый план задачу с запланированной/начавшейся/неопределённой отправкой. Действует существующая защита доставки задач.
- Внутреннее уведомление не дублируется в WhatsApp, Telegram, email или push. Проверяются доступ получателя к задаче и его настройки уведомлений.
- Старые команды Control продолжают использовать существующие обработчики. Массовой миграции прошлых подтверждений и истории в ActionRun не делалось.

## Перед выпуском

1. Визуально проверить новую страницу на компьютере и телефоне. Инструмент сообщил `Local browser use is disabled in Work settings`; обход другим способом не выполнялся.
2. Провести Linux/PostgreSQL-проверку и Docker-сборку. PGlite не доказывает поведение отдельных PostgreSQL-процессов при нагрузке. Контейнерный движок и локальный PostgreSQL ранее отсутствовали.
3. Согласованно обновить API и все фоновые обработчики после проверки миграции. Старые обработчики не знают `ai.action_run`; смешанный выпуск может остановить новый тип события как неподдерживаемый.
4. Проверить на тестовой компании создание/подтверждение/отмену плана после выпуска и журнал очереди. Новые планы не должны запускаться до готовности всех обработчиков.

Рабочая база, каналы, платежи и настройки клиентов этим этапом не изменялись; сообщения реальным адресатам не отправлялись. Публикация ветки и деплой не выполнялись.
