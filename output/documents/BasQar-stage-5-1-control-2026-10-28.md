# BasQar — этап 5.1: точные периоды и выборки Control

Дата: 28 октября 2026 года.

Это первая часть этапа 5 из аудита от 25 октября. Изменения сделаны в общем обработчике Control для кабинета и WhatsApp. Рабочий сервис не обновлялся, реальные сообщения не отправлялись.

## Что исправлено

1. **Календарные периоды.** «Эта неделя» означает понедельник–воскресенье в часовом поясе компании. «Последние 7 дней» остаётся отдельным периодом. Поддерживаются прошлые неделя и месяц, текущие месяц и год, весь период и конкретные даты. Даты «с / по» включены в выборку; в ответе видны границы и часовой пояс. Неизвестный период не заменяется молча на «сегодня».
2. **Мои задачи, команда, выбранный сотрудник.** «Мои» сохраняется при разборе разговорных формулировок. Запрос команды или другого сотрудника проверяет права. Команда здесь означает всю доступную команду компании; отдельная иерархия подразделений в этом этапе не добавлялась.
3. **Полное количество и короткий список.** Сначала считается всё множество подходящих задач, заявок или последних сделок. Затем отдельно загружается ограниченный список. В чате показано до восьми записей и явно указаны общее количество и количество показанных. Поиск задачи выполняется в базе, а не внутри первых ста ранее загруженных задач.
4. **Сроки и завершение задач.** «На сегодня» включает незавершённые задачи со сроком сегодня. Старые, будущие и бессрочные задачи не подмешиваются в этот список. Просроченные задачи считаются отдельно. «Завершённые за период» отбираются по дате завершения; обычный период задач относится к сроку. Подзадачи не дублируют родительские задачи в итогах.
5. **Связь с клиентом.** Задачи выбранного клиента находятся по прямой связи, заявке, сделке и диалогу. В списках сохраняются имя и доступный телефон. Идентификатор WhatsApp LID не выдаётся за номер телефона.
6. **Заявки без ответа.** Запрос «Какие заявки сегодня остались без ответа?» отбирает пересечение: заявка получена сегодня и сейчас ожидает ответа. Закрытые и архивные заявки не включаются. Это текущий статус ответа, а не восстановление исторического состояния на конец дня.
7. **Уточнение периода.** После списка или отчёта можно написать «А за вчера?», «А за прошлую неделю?» или «Ал өткен ай?». Сохраняются выбранный сотрудник, клиент и поддерживаемые фильтры. Без предыдущего подходящего запроса Control уточняет, для какого отчёта нужен период.
8. **Ограничения команд.** Модель не может передать произвольный фильтр в неподходящий инструмент. Например, команда общей статистики с именем сотрудника либо отчёт о текущей воронке «за прошлую неделю» не исполняются как будто фильтр применён. При недостатке данных требуется уточнение.
9. **История и права.** Сохранённый ответ из WhatsApp показывается в истории кабинета только при совпадении актуальной версии прав. Отзыв доступа не оставляет старый ответ с данными команды видимым в истории Control. Контекст и исполнение команд продолжают повторно проверять права.

## Проверенные примеры

| Запрос | Результат |
|---|---|
| «Какие у меня есть задачи на сегодня?» | Только свои незавершённые задачи со сроком сегодня. |
| «Покажи просроченные задачи моей команды» | Полный итог и короткий список в пределах разрешённого доступа. |
| «Завершённые задачи за сегодня» | Отбор по дате завершения, независимо от прежнего срока. |
| «Какие заявки сегодня остались без ответа?» | Дата поступления и текущий признак ожидания ответа применяются одновременно. |
| «Подготовь отчёт по продажам за текущий месяц» | Сводка по датам закрытия сделок с точными границами месяца; файл не создаётся. |
| «А за вчера?» после выбора сотрудника | Тот же сотрудник, новый период; повторный вызов модели не требуется. |
| «Осы аптадағы сатылымдарды көрсет» | Продажи за текущую календарную неделю. |
| «Менің командамның мерзімі өткен тапсырмаларды көрсет» | Просроченные задачи команды с проверкой прав. |
| «Бүгін жауапсыз қалған өтінімдерді көрсет» | Полученные сегодня заявки, ожидающие ответа. |

Отчёт продаж использует сумму выигранных сделок. В ответ добавлено пояснение, что эта сумма не подтверждает поступление денег. Разделение продаж, поступлений и прогноза во всей аналитике остаётся отдельной частью общего плана.

## Проверки

Использовались отдельные локальные базы PGlite. Внешние сервисы отключены или заменены тестовыми ответами. Проверены реальные серверные функции, очередь WhatsApp, история и подтверждения, но не живой ответ внешней языковой модели и не доставка через настоящий WhatsApp.

| Набор | Успешно |
|---|---:|
| Очередь, разбор и исполнение WhatsApp Control (`controlChat`) | 44 |
| Языковые сценарии (`controlLanguage`) | 4 |
| Периоды, границы, фильтры и подписи (`controlPeriods`) | 6 |
| Точные выборки, доступ и контекст (`controlReadPrecision`) | 10 |
| Control в кабинете (`controlWeb`) | 11 |
| HTTP API, подписи, права и подтверждения (`aiControl`) | 16 |
| **Всего уникальных тестов этапа** | **91** |

Дополнительно прошли проверка типов API, веб-приложения, мобильного приложения и контрактов; сборка веб-приложения и проверка изменений. Существующее предупреждение о больших частях веб-сборки остаётся: начальный JavaScript 1 099,6 КБ, gzip 279,0 КБ; ограничения сборки не менялись.

Контрольные случаи: 121 просроченная задача; поиск вне прежнего окна в 100 записей; 35 заявок без ответа; неизвестная дата завершения; связь задачи только с диалогом; другой клиент и другая компания; отзыв прав; граница месяца; начало календарной недели; смена года и переход часового пояса на летнее время.

## Следующая часть этапа 5

Весь этап 5 ещё не завершён. Далее нужны отдельные точные инструменты для четырёх запросов из исходного задания:

1. Сделки без изменений за указанное число дней — с явным определением, что считается изменением.
2. Клиенты с действительно отправленным коммерческим предложением и без назначенного следующего контакта.
3. Причины проигрыша сделок за выбранный период.
4. Сделки с ожидаемой оплатой на этой неделе — по сроку счёта или подтверждённой договорённости, с исключением оплаченных и отменённых.

В эти инструменты нельзя просто передать неподдерживаемый фильтр существующего общего отчёта. Для них требуются отдельные выборки и приёмочные сценарии. Общая проверка реальных интеграций, PostgreSQL/Docker и публикация изменений также не входят в результаты этой локальной проверки.
