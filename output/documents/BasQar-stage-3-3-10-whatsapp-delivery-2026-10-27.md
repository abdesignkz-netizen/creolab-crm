# BasQar — этап 3.3.10: результат отправки WhatsApp QR и Cloud

Дата: 27 октября 2026. Изменения реализованы и проверены локально. На рабочий сервис не развёрнуты.

## Что изменилось для пользователя

У новых сообщений сотрудника через WhatsApp QR и Cloud доступна подробная проверка результата: получатель, текст и каждый файл со своим состоянием и номером отправки у провайдера. Принятый текст не означает, что вложения тоже отправлены.

Если подтверждение потерялось, руководитель может записать результат независимой проверки конкретной части с обязательным пояснением. Сверка сохраняет сведения, но ничего не отправляет клиенту. После подтверждения отсутствия отправки доступен отдельный повтор только неотправленных частей. Части с неизвестным результатом блокируют повтор; уже отправленные части пропускаются.

Сверка и запрос повтора записываются в журнале действий и истории клиента. Менеджеру доступен просмотр его диалога; сверка и повтор требуют прав руководителя. Подсказки доступны на русском и казахском.

Для Cloud подсказка предлагает проверку у получателя или в независимом журнале провайдера. Собственная запись BasQar не считается доказательством внешней доставки. Ручное подтверждение отделено от подтверждения WhatsApp и не получает выдуманный номер отправки.

## Исправленные сценарии

- Текст и файлы имеют отдельные сохранённые состояния. Сбой второго файла не требует повторять текст и первый файл.
- Каждая попытка повтора имеет отдельную запись очереди и идентификатор. Старый запрос, отложенная очередь и двойное нажатие не запускают новую попытку повторно.
- При потере подтверждения система сохраняет неизвестный результат. Восстановление после перезапуска само ничего не отправляет.
- Если процесс прервался до начала отправки, не начатое задание QR возвращается в очередь. Если обращение к провайдеру уже началось, требуется сверка результата.
- Изменение режима диалога, доступа отправителя, подключения, получателя, содержимого или исходного файла останавливает оставшиеся части. Принятые части остаются принятыми.
- Смена подключения после постановки в очередь теперь завершает старую попытку отменой; сообщение не остаётся навсегда в состоянии «в очереди».
- Для Cloud проверяются учётные данные и окно ответа после входящего сообщения, в том числе повторно после загрузки файла и перед каждой отправляемой частью.
- Подписанные уведомления Cloud обрабатываются отдельно для каждой части. Уведомление о прочтении текста не помечает вложение прочитанным. Раннее уведомление, пришедшее раньше ответа на запрос отправки, не теряется.
- Позднее уведомление от старой попытки не перезаписывает результат нового повтора. Статусы доставки и прочтения не понижаются запоздалым уведомлением «отправлено».
- Предупреждение о недоставке снимается после успешного повтора или подтверждения доставки. При этом сохраняется необходимость ответить на более новый вопрос клиента.
- В рассылках сохраняется связь с исходным получателем и историей сообщения. Изменение телефона, клиента, текста или подтверждения рассылки блокирует повтор старой попытки.
- Пауза рассылки сохраняет ожидающее задание Cloud для продолжения. Общая кнопка повторения рассылки не пересылает целиком сообщение, для которого уже есть история отправки частей.

Принятие сообщения провайдером, доставка и прочтение — разные факты. Этот этап не обещает абсолютную гарантию внешней доставки: при неизвестном результате повтор остаётся закрыт до независимой проверки.

## Проверки

В последних успешных запусках каждого набора прошли 228 серверных тестов. Наборы запускались в отдельных тестовых базах PGlite, внешние провайдеры заменены имитацией.

| Набор | Успешно |
| --- | ---: |
| Новая сверка WhatsApp QR/Cloud | 59 |
| Подключения WhatsApp, обычная отправка, голосовые сообщения | 52 |
| Существующая доставка WhatsApp | 26 |
| Рассылки | 14 |
| Существующая сверка отправок | 26 |
| Сверка Telegram | 38 |
| Ответы ИИ в каналах | 11 |
| Фоновое восстановление QR | 2 |
| **Всего** | **228** |

Дополнительно прошли 58 проверок логики интерфейса, проверка типов сервера и клиента, сборка интерфейса и проверка формата изменений. Проверки логики интерфейса не заменяют проверку в браузере.

Начальный JavaScript: 1099,6 КБ, gzip 279,0 КБ. Ограничение размера не менялось. Окно проверки загружается отдельно: 18,99 КБ, gzip 5,72 КБ. Сохраняется предупреждение сборщика о крупных пакетах; начальный пакет близок к установленному пределу.

В предварительных запусках исправлены тестовые данные QR: имитация подключения должна содержать реальный для этого теста номер отправителя. Ожидание старого состояния «неизвестно» при отмене после принятого текста заменено проверкой подтверждённого частичного результата. Один запуск проверки голосовых сообщений при параллельном выполнении двух тяжёлых наборов получил состояние, отличное от ожидаемого; повтор всего набора подключений отдельно прошёл 52/52. Точная причина этого единичного расхождения не установлена, проверки не ослаблялись.

Подробные ссылки на журналы запусков и ограничения: `BasQar-stage-3-3-10-whatsapp-delivery-2026-10-27-checks.json`.

## Границы этапа

- Изменения относятся к новым сообщениям сотрудника и отправкам рассылок через прямые подключения QR/Cloud с полной историей частей. Прежние записи без такой истории не становятся разрешёнными для повтора по предположению.
- Отдельный интерфейс сверки неизвестных ответов ИИ ещё не добавлен. Это следующий этап.
- Рабочие данные и настройки компаний не менялись. Реальным клиентам сообщений не отправляли. Изменений схемы базы нет.
- Визуальная приёмка на компьютере и телефоне не выполнена: инструмент управления браузером возвращает `Local browser use is disabled in Work settings`, доступных браузеров нет.
- Реальная доставка WhatsApp, конкуренция отдельных рабочих процессов PostgreSQL и полная Docker-сборка не проверены.
- После этапа сверки ответов ИИ остаются визуальная приёмка и выпуск, затем дальнейшая работа над единым процессом обращений, сделок, задач и документов.

Справочный материал по Cloud: [официальная документация SDK Meta](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/) и [приём уведомлений](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/receivingMessages/). Эти материалы использовались как справочные; успешная проверка реального подключения ими не подменяется.
