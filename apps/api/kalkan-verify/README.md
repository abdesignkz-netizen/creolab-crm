# Проверка подписей договоров

CRM принимает подпись только после двух успешных проверок: `cryptoStatus=VERIFIED`
и `authorityStatus=VALID`. Отсутствие сервиса, недоступность OCSP/CRL или результат
`UNCHECKED` не должны менять договор на подписанный. Требуются проверенные подписи
исполнителя и заказчика для одной текущей версии договора.

Сервис принимает только detached CMS с одним подписантом и проверяет подпись по
переданным байтам договора. Доверенные сертификаты УЦ берутся из установленного
НУЦ SDK и `KALKAN_CA_DIR`; сертификаты из входящего CMS не становятся доверенными УЦ.

## Проверка без настоящих договоров и ключей

Нужны JDK и официальный Kalkan SDK. Из корня проекта:

```sh
export KALKAN_JAR=/path/to/official/sdk/lib/kalkan.jar
export SIGNING_TEST_CLASSES=/tmp/basqar-kalkan-test-classes
mkdir -p "$SIGNING_TEST_CLASSES"
javac -cp "$KALKAN_JAR" -d "$SIGNING_TEST_CLASSES" \
  apps/api/kalkan-verify/VerifyServer.java apps/api/kalkan-verify/VerifyServerTest.java
java -cp "$SIGNING_TEST_CLASSES:$KALKAN_JAR" VerifyServerTest
```

Тест создаёт временные ключи только в памяти для RSA и ГОСТ-2015, проверяет исходный
файл и отказ для другого файла и attached CMS. Это проверка криптографии, а не
доверия к настоящему сертификату НУЦ или подключения пользовательского NCALayer.
Синтетические сертификаты не добавляются в доверенные.

API-сценарии и отрицательные проверки входят в `npm test` и используют временные
базы. Тестовый HTTP-сервис `testKalkan.ts` проверяет RSA CMS через OpenSSL и имитирует
статус доверия; он не используется в рабочем приложении.

## Применение изменений

После изменения Java-исходника сервис нужно пересобрать и перезапустить обычным
способом для окружения. Уже запущенная JVM продолжает использовать старые классы.
Настройки рабочего сервиса (`KALKAN_LIB_DIR`, `KALKAN_VERIFY_SECRET`, `KALKAN_CA_DIR`,
`KALKAN_CRL_DIR`, `KALKAN_OCSP`) при перезапуске необходимо сохранить.

Ранее сохранённые подписи со статусом `PARSED` не становятся проверенными после
обновления. Их исходные CMS и файл договора требуют отдельной повторной проверки;
историю подписей автоматически не изменяем.
