# Сотрудники, журнал действий и формирование договоров

## Сотрудники и журнал

В настройках компании доступны приглашения сотрудников по ссылке. Использован существующий механизм Invitation. Лимит берётся из действующих условий компании, включая оплаченные дополнительные места. Активные сотрудники и непросроченные приглашения занимают места. Создание/принятие приглашений сериализовано блокировкой компании; при принятии повторно проверяется действующий лимит. Есть обновление ссылки и отмена приглашения. Письмо автоматически не отправляется.

Журнал показывает русские названия действий и сущностей, понятные суммы, даты, роли и тарифы. Служебные ключи, идентификаторы и JSON не выводятся в интерфейсе. Исходные записи сохранены. Поиск поддерживает русские названия действий.

Проверено: 7 новых тестов сотрудников/журнала, 15 тестов Platform Admin; 9 состояний интерфейса, ширины 390–1440 px. Web typecheck и production build прошли.

## Причина ошибки договора

Ошибка воспроизведена на локальном Word-договоре: исходник и сохранённый шаблон открывались, но после заполнения создавался некорректный Word XML. Регулярное выражение захватывало внешнюю таблицу до закрывающего тега первой вложенной таблицы; после замены оставались закрывающие теги ячеек без соответствующих открывающих тегов. LibreOffice не создавал PDF.

Обход таблиц теперь учитывает вложенность. Заменяются только таблицы позиций, внешняя структура, условия и подписи сохраняются. Вложенные таблицы используют ширину родительской ячейки вместо ширины всей страницы.

Добавлен синтетический шаблон без клиентских данных и сквозной тест: загрузка шаблона → заполнение → получение PDF → проверка сохранности условий, подписей и нового заказа. Проверка Docker-сборки теперь также конвертирует заполненный шаблон с вложенной таблицей.

Проверено:
- 15 тестов contractTemplate, 6 contractPdf, 2 wordDocumentConversion, 5 documentsPhase2 — 28 успешно.
- Проверка реального конвертера: DOC, DOCX и заполненный шаблон с вложенными таблицами → PDF.
- В браузере: автоматическое открытие PDF после генерации, скачивание PDF и DOCX, отображение на 1440 и 390 px, без ошибок JavaScript и HTTP 5xx.
- PDF с вложенной таблицей проверен визуально; сумма видна внутри ячейки.

Общая проверка типов API по-прежнему сообщает ранее существовавшую ошибку billingService.ts:288 (nullable billingPeriod). Новых ошибок типов в изменённых файлах нет.

Изменения не публиковались и не развёртывались на рабочем сервере. После обновления сервера договор нужно сформировать повторно из существующего шаблона. Новые миграции не нужны.
