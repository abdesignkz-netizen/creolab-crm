# Нумерация документов и редактирование АВР

В разделе «Настройки → Компания → Нумерация документов» задаётся начальное
число отдельно для договоров (DOG), счетов (INV), АВР и ЭСФ. Рядом показан
следующий номер по сохранённым настройкам. Изменение не перенумеровывает
существующие документы и не уменьшает уже использованный счётчик.

Счётчики хранятся в Tenant.settingsJson.documentNumbering, отдельная миграция
не требуется. При первом использовании учитываются имеющиеся номера,
прежняя нумерация по количеству документов и история удаления договоров.
Выдача номера и создание документа выполняются в транзакции с блокировкой
организации. Удаление документа не возвращает его номер в автоматическую
последовательность. Предпросмотр договора из шаблона резервирует номер,
чтобы последующее сохранение сохраняло номер из PDF; отменённые просмотры
могут оставлять пропуски. Счётчик не сбрасывается при смене года.

Кнопка создания АВР в сделке открывает редактор до сохранения. В нём можно
задать номер (до 40 символов), дату и позиции. Пустой номер при создании
означает автоматическую нумерацию; при редактировании сохраняется прежний
номер. Подписываемые и отправленные АВР остаются недоступны для правки.
Номера AVR-2026-0001 и 26-0001 считаются совпадающими. Произвольные номера
сохраняются в Excel/PDF; автоматические номера выводятся в прежнем виде
YY-NNNN. В PDF восстановлена нижняя граница блока номера и даты.

Проверено: тесты documentNumbering, avrWorkflow, avrExcel, contractDeletion,
documentsPhase1/2/8, contractTemplate и avrEditor; типы API/web и сборка web.
PDF отрисован Poppler и проверен визуально, включая увеличенный блок номера.
В avrSigning остаются два сбоя, воспроизведённые также на исходном HEAD:
ожидание сокращённого имени «ТОО» вместо полного названия и последующая
проверка реестра. Браузерная проверка недоступна из-за ошибки запуска среды
CUA/Chrome; тесты API выполнялись с отдельными временными базами и mock ЭСФ.

## Счета на оплату

Редактор счёта поддерживает собственный номер (до 40 символов), дату, позиции
и долю оплаты. Пустой номер нового счёта выдаётся из счётчика INV; пустое поле
при правке сохраняет прежний номер. Значения INV-2026-0500 и 26-0500 считаются
одним номером; ручной номер этой серии сдвигает следующий автоматический номер.
Произвольный номер, например СЧ-125/А, сохраняется в PDF полностью.

Создание и редактирование выполняются с блокировкой организации, правка также
блокирует счёт и проверяет updatedAt. Параллельное создание по одной сделке
возвращает один черновик. Повторное открытие не заменяет отредактированные
позиции данными сделки. При правке ранее сформированный PDF сбрасывается.
Импортированные PDF и счета в неизменяемых статусах защищены и в API,
и в редакторе. В карточке сделки сохранена кнопка создания через редактор;
кнопка создания черновика в обход редактора убрана.

Дополнительно проверены invoiceEditor (11 интеграционных сценариев и тест
арифметики), invoicePdf, documentNumbering, documentsPhase3; API/web typecheck,
сборка web. Счёт с ручным номером отрисован Poppler и проверен визуально.
