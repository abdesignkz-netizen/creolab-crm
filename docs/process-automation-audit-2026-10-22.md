# Проверка автоматизации и контроля — 22 октября 2026

Проверена цепочка: входящее обращение → правила ответа ИИ → передача сотруднику → задача → фоновое выполнение → история и уведомления → команды BasQar Control. Проверка проведена локально, на изолированных базах, с отключёнными либо подменёнными внешними провайдерами.

## Исправления

1. Просроченная задача больше не считается зависшей только из-за старого срока. Фоновый обработчик получает отдельный захват на 90 секунд и продлевает его каждые 30 секунд. Другой обработчик не запускает эту запись одновременно. Срок задачи остаётся прежним.
2. После прерывания отправки её неизвестный результат не превращается в автоматическую повторную отправку. Действие и задача получают ошибку с указанием проверить результат. Напоминания о договорённостях и чтение статусов ИС ЭСФ могут восстановиться автоматически; это не подписание и не отправка документов.
3. Постановка задачи в очередь и восстановление отсутствующей записи используют блокировку задачи. Два одновременных запроса не оставляют две активные записи. Дочерние задачи групповой отправки не получают отдельную восстановленную отправку.
4. Фоновый исполнитель больше не создаёт подтверждение от имени пользователя. Используется сохранённое подтверждение; отозванное либо отсутствующее требует проверки и повторного подтверждения. Для групповой отправки также сохраняются подтверждённые снимки, без фоновой переподготовки текста и файлов.
5. Увольнение/деактивация подтвердившего сотрудника не переключает выполнение на другого сотрудника или владельца. Доступ проверяется для подтвердившего пользователя.
6. Неудачная отправка больше не помечает фоновое действие выполненным. Ответственному создаётся уведомление о необходимости проверки; Control и личный Telegram получают его согласно настройкам. Ошибка одной задачи не блокирует следующую в очереди.
7. Доставки уведомлений имеют постоянные идентификаторы. Одновременная обработка одного события не создаёт дубли внутри CRM и Web Push. Отправку Web Push захватывает один обработчик, сетевой запрос имеет таймаут.
8. Неизвестный тип фонового действия помечается ошибкой вместо ложного успешного завершения. Документация уведомлений приведена в соответствие с реализацией.

Новые проверки воспроизводят параллельные обработчики, долгую отправку, прерывание процесса, восстановление очереди, утраченное подтверждение, потерю доступа сотрудника, неудачную отправку, сохранение истории и однократную доставку уведомления. Успешная отправка проверена через подменённый WhatsApp-мост: одна операция и одна запись в истории при двух одновременно работающих фоновых циклах.

Проверки типов API и web прошли. Сборка web прошла вместе с проверкой бюджета размера. Остались предупреждения сборщика о комментариях сторонней зависимости Zod и размере общего JavaScript-пакета; это не ошибки выполнения тестов.

## Границы проверки

- Рабочая база и реальные переписки не изменялись. Новая отправка клиенту, платёж или отправка документов в ИС ЭСФ не выполнялись.
- В локальном браузере удалось войти в тестовый кабинет, открыть обзор и перейти в Control. После этого инструмент снова сообщил об отключённом управлении браузером в настройках Work. Заключительная ручная проверка команд и мобильного интерфейса в этом проходе не завершена; соответствующие серверные сценарии проверены тестами.
- Не подтверждены актуальное состояние рабочих подключений и доставка у внешних провайдеров. Отсутствие ошибок в этих тестах не является гарантией отсутствия любых сбоев рабочего сервиса.
- Универсальной эскалации всех уведомлений через 5/15 минут нет. Действуют реализованные напоминания о договорённостях, очередь уведомлений и правила Control.
- Изменения локальные; публикация в рабочий сервис в рамках этого прохода не выполнялась.
