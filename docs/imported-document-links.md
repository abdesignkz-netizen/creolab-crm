# Реквизиты импортированного договора в связанных документах

`documentOrganization` собирает реквизиты исполнителя для документов сделки:
сначала сохранённые настройки организации, затем недостающие поля из
`reviewedImport.seller` события `document.import_pdf` соответствующего договора.
Это подтверждённые пользователем поля импорта, а не новое распознавание файла.

Источник применяется при проверках готовности договора, счёта, АВР и ЭСФ,
генерации PDF, сборке данных АВР/ЭСФ и банковских реквизитов для ИС ЭСФ,
подготовке подписания и отображении исполнителя на публичной странице подписи.
Заполненные настройки не перезаписываются. При несовпадении БИН/ИИН
исполнителя импорт не используется для дополнения организации.

Договор выбирается только внутри нужной организации и сделки. При явной
ссылке используется именно этот договор; иначе предпочтение отдаётся
подписанному договору, затем последнему действующему. Отменённые договоры
не используются. Чтение не изменяет настройки, статус подписи или отправки.

Механизм работает и для старых импортов с сохранённым `reviewedImport`.
Если этих данных нет, недостающие поля продолжают показываться пользователю;
система не выдумывает реквизиты. Отдельная команда переноса в настройки
организации сохранена.

Телефон контакта включён в загрузку карточки и списка сделок: ранее
повторная выборка контакта теряла сохранённые способы связи.

Проверка интеграции моделирует старый импорт с пустыми настройками:
проверяет все четыре readiness-ответа, реквизиты обеих сторон в АВР и ЭСФ,
создание PDF счёта, сохранение связи с договором и телефон в карточке.
Проверяются также несовпадающий БИН, чужая сделка/организация и сохранение
вручную заполненных настроек. Подпись, ТРУ и отправка в ИС ЭСФ остаются
самостоятельными условиями готовности.
