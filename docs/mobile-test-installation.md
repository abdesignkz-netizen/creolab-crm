# BasQar — установка проверочной мобильной сборки

Эта инструкция относится к артефактам workflow `Mobile acceptance (no store submission)` из ветки `codex/mobile-store-release`. Они предназначены для проверки и не отправлялись в магазины.

Проверенная сборка от 03.11.2026: коммит `79193890a25c30706bf3a92c8a6dd55c4d1ec471`, [успешный запуск № 41640572062](https://github.com/abdesignkz-netizen/creolab-crm/actions/runs/41640572062).

- [Android: архив с APK и AAB](https://github.com/abdesignkz-netizen/creolab-crm/actions/runs/41640572062/artifacts/13233138345).
- [iOS: приложение для симулятора](https://github.com/abdesignkz-netizen/creolab-crm/actions/runs/41640572062/artifacts/13232184185).

Эти архивы доступны до 10.11.2026; для скачивания нужен вход в GitHub. После истечения срока потребуется новая сборка. Контрольные суммы архивов и сведения о проверках приведены в [отчёте](../output/documents/BasQar-mobile-cloud-2026-11-03.md).

## Как получить Android APK

1. Открыть завершённый успешный запуск в [GitHub Actions](https://github.com/abdesignkz-netizen/creolab-crm/actions/workflows/mobile-acceptance.yml).
2. Проверить ветку, дату и исходный коммит. Состояние `success` должно быть у задачи `android`, а не только у общих проверок.
3. Войти в GitHub и в разделе Artifacts скачать `basqar-android-CI-ONLY-not-for-store`.
4. Распаковать ZIP. Для телефона нужен `app-release.apk`; файл `.aab` предназначен для дальнейшей проверки пакета, напрямую он не устанавливается.
5. Сверить файл по `SHA256SUMS.txt`; `SOURCE_REVISION.txt` содержит коммит сборки.
6. Перенести APK на тестовый Android, разрешить установку только для выбранного приложения-источника и установить BasQar. После установки разрешение источника можно выключить.

Артефакты хранятся 7 дней. Каждый облачный запуск использует новый временный тестовый ключ, не ключ магазина. Поэтому обновление APK от другого запуска поверх предыдущего может не установиться. Удалить старый тестовый BasQar и установить новый; локальный вход при этом сбросится, данные компании на сервере не удаляются. Не использовать этот временный ключ для Play или постоянного распространения.

## Что можно проверить без работающего сервера

- Установка и запуск, имя и иконка BasQar, экран запуска.
- Понятное сообщение о недоступности сервера вместо белого или зависшего экрана.
- Кнопка «Повторить», отключение/включение интернета и повторный запуск.
- Портретный/альбомный режим, верхняя панель, меню и системная кнопка «Назад».

Состояние `Service Suspended` на bsqr.kz означает остановку сервера на Render. Оно не даёт проверить вход, переписку, задачи, файлы и интеграции. Наличие установленного APK само по себе не подтверждает их работу.

## После восстановления совместимого сервера

Сначала развернуть проверенный API и web мобильной ветки обычным процессом выпуска. `GET /api/v1/mobile/config` должен возвращать JSON с `protocolVersion: 1`. Только затем проходить полную [матрицу приёмки](mobile-store-checklist.md) на отдельной тестовой компании. Подключение к другому тестовому HTTPS-серверу допускается только специальной development-сборкой, а не подменой адреса в production-пакете.

Без настроенных APNs/FCM и реального EAS project ID push-уведомления внутри этой проверочной сборки не считаются рабочими. Уведомления в самом кабинете используют существующий сервер.

## iOS

Артефакт `basqar-ios-simulator-NOT-IPA` содержит архив приложения для симулятора. Он не устанавливается на физический iPhone и не подходит для App Store.

На Mac с полным Xcode распаковать архив, запустить подходящий iOS Simulator и установить `.app` командой `xcrun simctl install booted /absolute/path/BasQar.app`. Запуск: `xcrun simctl launch booted kz.bsqr.app`.

Для физического iPhone требуется отдельная подписанная сборка, Apple Developer Team и зарегистрированное устройство либо TestFlight. Отправка в TestFlight/App Store выполняется только после разрешения владельца.

## Как сообщить результат

Записать коммит из `SOURCE_REVISION.txt` для Android или из страницы запуска GitHub для iOS, модель телефона/симулятора, версию ОС, шаги до ошибки, ожидаемый и фактический результат. Скриншоты делать без настоящей переписки, паролей и персональных данных клиентов. Отдельно отмечать «не проверено», если сценарий зависит от сервера или внешнего подключения.
