# BasQar Control: личный WhatsApp сотрудника

Изменения подготовлены локально 18.10.2026. Производственные настройки не менялись, реальные сообщения не отправлялись.

## Подключение

1. Подключить WhatsApp компании через QR или Cloud API.
2. Открыть «Настройки → BasQar Control», включить Control для компании, разрешить доступ сотруднику и выбрать его права.
3. Выбрать WhatsApp компании, указать отдельный личный номер и получить код.
4. С личного номера отправить `Control <код>` на выбранный номер компании. Код действует 30 минут; после пяти неверных попыток нужен новый.
5. Обновить статус. Настроить язык ответов и, для QR, утреннюю/вечернюю сводку. Новые сводки по умолчанию выключены.

Один номер не может принадлежать разным сотрудникам одной компании. Повторная выдача кода сохраняет настройки прежнего подключения. Номер компании нельзя использовать как личный номер получателя.

## Использование

«Меню» / «Мәзір» возвращает пронумерованные пункты: сводка, внимание, сегодняшние задачи, продажи, поиск клиента, создание задачи. Достаточно ответить номером пункта. Можно писать свободным текстом на русском или казахском. Состав меню зависит от прав.

Поддерживаются 26 команд: сведения о заявках, клиентах, сделках, воронке, выручке, команде и задачах; создание и изменение задач, завершение и назначение задачи, заметка сделки, смена этапа и ответственного сделки. Удаление, массовые изменения и отправка клиентам из этого чата не доступны. Существующие внешние Control API сохраняются отдельно.

Примеры: «Задачи на сегодня», «Продажи за неделю», «Найди клиента Айбек», «Создай задачу подготовить КП завтра к 15:00». Неоднозначные имена требуют выбора записи. Выбранный клиент сохраняется в контексте на 30 минут. Новая команда в меню отменяет ожидающее подтверждение.

Любая запись сначала показывает действие, выбранный объект, срок и ответственного. Выполнение требует отдельного `Подтвердить <код>` / `Растау <код>` в течение 10 минут. Простое «да» не выполняет запись. «Отмена» / «Болдырмау» прекращает команду. При изменении прав проверяется доступ заново.

## Доставка и ограничения

- Входящее сообщение маршрутизируется в Control до создания клиентской карточки или диалога. Отключённый личный номер в настроенном канале не передаётся клиентскому ИИ.
- Номер берётся из данных WhatsApp, включая PN-алиас для LID. Protobuf-преобразование больше не теряет этот алиас. Цифры LID никогда не считаются телефоном.
- Модель разбирает запрос в ограниченную схему; сведения и ответы формируются из разрешённых данных CRM. Меню и простые запросы данных работают без вызова модели. Свободные формулировки и создание задач требуют доступного настроенного провайдера ИИ. Текст задачи после двоеточия также разбирается на срок, ответственного и клиента: эти параметры не превращаются в часть названия.
- Очередь, контекст, подтверждения и ключи повторов хранятся в БД. Обработка и доставка сериализованы для каждого личного номера и подключения. Сообщения с одинаковым временем WhatsApp упорядочены по отдельному последовательному номеру поступления, а не случайному UUID. Неопределённая отправка не повторяется автоматически.
- Утренние и вечерние сводки учитывают часовой пояс компании и выбор будней. Совпавшие или накопившиеся части одной свежей сводки объединяются. Опоздание более 30 минут не восполняется старыми отчётами. Уведомления о событиях и их объединение настраиваются в существующей панели ниже.
- QR выполняет запросы и плановые сводки без открытого браузера. Cloud API отвечает на свежий подписанный входящий запрос; плановые сводки для него выключены до реализации согласованных шаблонов Meta. Green API продолжает использовать прежний внешний Control API и уведомления; новый непосредственный чат включается только для QR/Cloud.
- «Принято WhatsApp» не означает прочтение. Журнал показывает подтверждённую приёмку, ошибку либо неопределённую доставку.

## Проверки

- `controlChat`: 35 проверок, включая подтверждение владения номером, блокировку подбора кода, границы компаний, изменение и отзыв прав, повторы, выбор клиента/сделки, перенос срока задачи, заметку сделки, сводки и реальные пути обработчиков QR/Cloud с подменой внешних провайдеров. Повторная проверка выявила и устранила потерю срока в команде с двоеточием и перестановку сообщений в пределах одной секунды. Дополнительно проверены назначение и завершение задач, смена этапа сделки, сохранение контекста при сводке, восстановление доставки после отключения и повторная инициализация схемы очереди.
- `aiControl`: 16; `controlNotifications`: 22; `whatsappConnections`: 52; `whatsappQrBackground`: 2 — успешно.
- Web: 39 проверок; проверка типов всех рабочих пространств; сборка web — успешно. Сохраняется предупреждение сборщика о размере основного JavaScript-файла.
- Браузер: 390×844 и 1440×1000, отсутствие горизонтального переполнения, сохранение языка и расписания, корректные статусы номера. Новых ошибок в консоли не обнаружено.
- `scripts/control-ui-smoke.mts` поднимает отдельный кабинет на 4487/4488, запрещает внешние запросы и не запускает отправляющие фоновые процессы.

Контрольная проверка на настоящем личном WhatsApp после публикации остаётся отдельным этапом; локальные тесты её не заменяют. Docker-сборка в этой работе не выполнялась.
