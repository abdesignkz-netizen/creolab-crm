# Проверка BasQar — 17 октября 2026

Проверен рабочий код и кабинет владельца CREOLAB на bsqr.kz. Изменения этой проверки ещё не опубликованы. В рабочем кабинете выполнялось чтение: новые платежи, отправка клиентам, подписание ЭЦП, отправка АВР/ЭСФ и изменение настроек не выполнялись. Изменение отметки прочтения при открытии диалога возможно по обычному поведению приложения.

## Исправления

1. **Повторная обработка фоновых событий.** API, отдельный worker и быстрый запуск обработки заявки могли одновременно взять одно событие. Добавлен атомарный захват в БД с продлением во время работы, восстановлением после остановки процесса и защитой от подтверждения устаревшим обработчиком. Проверены конкурирующие обработчики, истечение захвата, продление и повтор после ошибки. Это не обещание строго однократной внешней отправки при любых сетевых сбоях: ограничения и идемпотентность провайдеров сохраняются.
2. **Потеря обработки входящей заявки.** Форма сайта и доверенные интеграции запускали сохранение задачи без ожидания. Заявка могла быть подтверждена отправителю до появления задачи в очереди. Теперь заявка, отметка принятого события и задача для ИИ сохраняются в одной транзакции. HTTP-ответ не ждёт выполнения ИИ; обработку подхватывает фоновый процесс. Повторные события не создают вторую задачу. В исходном полном прогоне эта гонка проявилась при завершении теста Meta; после изменения проверяется и наличие задачи сразу после ответа.
3. **Запуск отдельного worker.** Рабочая команда больше не зависит от dev-пакета `tsx`; таймер удерживает самостоятельный процесс активным. API и worker используют разные цели общего Dockerfile с одинаковыми средствами обработки документов и речи. В Compose добавлены общие настройки и постоянный том файлов. Локально проверен запуск с production-настройками, работа после интервала опроса и завершение по SIGTERM. Полный контейнер не собирался.
4. **Ложные выводы о потерях в воронке.** Разность числа сделок на текущих стадиях больше не выдаётся за потерянных клиентов, а их отношение — за конверсию. Ответ аналитика объясняет, что для этого нужна история переходов. Исправлены и обычный ответ, и инструкции модели; текущие количества и доли стадий остаются доступны.
5. **Несогласованные статусы ИИ.** Доступность старого WhatsApp-сервиса больше не означает «ИИ активен». Служебный `autoReply` старой интеграции также больше не показывается как достоверный выключатель ИИ. Старое подключение представлено отдельно от QR/Cloud и других каналов, использующих этот флаг. Уточнены подсказки настройки: владелец публикует знания и инструкции, администратор платформы отвечает за доступность модели. Добавлены переходы к цели ИИ и правилам ответа с учётом прав пользователя и языков интерфейса.
6. **Надёжность проверки.** Тесты ИС ЭСФ явно включают глобальный контур там, где он нужен сценарию. Неизвестное имя тестового файла теперь останавливает запуск, а не незаметно пропускается. Реальные ограничения доступа не ослаблялись.

- Итоговый полный прогон API/контрактов: **142/142 файла, 1097/1097 сценариев**, без пропусков и отменённых тестов. Каждому файлу выделяется отдельная PGlite-база; внешние провайдеры отключены или заменены тестовыми ответами. Покрыты авторизация, разграничение компаний и ролей, биллинг, жизненный цикл CRM, документы, глобальный доступ к ИС ЭСФ, правила ИИ, интеграции и фоновые задачи.
- Веб-тесты: **39/39**, без пропусков.
- TypeScript всех пакетов: успешно.
- Production-сборка сайта и ограничение размера начальной загрузки: успешно. Начальный JS — **1064,4 kB**, gzip **272,0 kB**. Предупреждение Vite о большом чанке остаётся; реальная скорость на слабой сети не измерялась.

- Проверки запуска API с Kalkan и конвертации Word (DOCX, DOC, вложенные таблицы): успешно; используются локальные инструменты, не полный Linux-образ.
- Локальный браузер: проверен исправленный ответ аналитики о воронке, ссылки в Green API и мобильная ширина 390 px для интеграций и правил ИИ. Горизонтального переполнения этих страниц нет; ошибок консоли в проверенных переходах не было.

## Оставшиеся ограничения

- В серверном наборе зависимостей npm audit от 17.10: **0** предупреждений. Полное дерево проекта по проверке 15.10: **29** (20 high, 9 moderate, 0 critical), преимущественно мобильная цепочка Expo/React Native. Это требует отдельного совместимого обновления; опасный автоматический откат/форсированная смена SDK не выполнялись.
- Docker отсутствует; пользователь выбрал продолжение без Docker. Linux-сборка, запуск общего образа и установка большой речевой модели в контейнере остаются непроверенными.
- Нагрузочное тестирование, нативные APK/IPA, реальная доставка всех внешних каналов, новая оплата, подписание/отправка в ИС ЭСФ не входят в подтверждённые результаты этого прохода.
- Глобальный переключатель ИС ЭСФ из предыдущего коммита и исправления этого аудита ещё нужно опубликовать. Наблюдения рабочего сайта относятся к установленной там версии.
