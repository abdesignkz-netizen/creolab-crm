# Материалы для обучения ИИ-менеджера

## Путь в интерфейсе

Настройки → ИИ-менеджер → «База знаний» (шаг 6 мастера).

1. Выберите «Загрузить материалы», «Добавить ссылку» или «Заполнить вручную».
2. Дождитесь извлечения текста. Для скана это может занять до 90 секунд.
3. Проверьте название, раздел, текст, цены, сроки и условия. Распознавание не подтверждает достоверность сведений.
4. Выберите новый материал или обновление существующего. При обновлении можно раскрыть прежний текст для сравнения.
5. Подтвердите проверку и добавьте материал в анкету.
6. Сохраните черновик, проведите проверочные диалоги на последнем шаге и опубликуйте настройки.

До публикации ответы действующего ИИ не меняются. Импорт не заполняет автоматически поля цели, сценария и правил общения: эти настройки остаются отдельными.

## Поддерживаемые источники

| Источник | Что извлекается | Ограничения |
| --- | --- | --- |
| PDF | Текст; страницы без достаточного текстового слоя распознаются OCR | До 20 страниц и 10 МБ; PDF без пароля |
| PNG, JPG, JPEG | Текст изображения с помощью OCR | До 10 МБ и 12 млн пикселей; каждое измерение до 12 000 пикселей |
| DOCX | Основной текст, таблицы, колонтитулы и сноски | Текст изображений не извлекается: загрузите их отдельно или сохраните документ в PDF |
| XLSX | Данные листов с сохранёнными значениями ячеек | До 10 листов, 2 000 строк и 50 столбцов на лист; формулы не пересчитываются |
| CSV | Текстовая таблица | UTF-8; те же ограничения по строкам и столбцам |
| TXT, MD | Текст | UTF-8 |
| Ссылка HTTPS | Доступный текст выбранной страницы, список ссылок на другие страницы того же сайта | До 2 МБ, 20 секунд; без выполнения JavaScript и авторизации |

Один файл обрабатывается за раз. Если материал слишком большой, пользователь получает сообщение о необходимости разделить или сократить его; текст не обрезается автоматически. Максимум — 40 дополнительных материалов и 65 000 символов суммарно для скомпилированных инструкций и знаний. Распознавание допускает до 120 000 символов в предварительном просмотре, чтобы можно было отредактировать текст до добавления.

### Рекомендуемый размер

Жёсткий предел — **10 МиБ (10 485 760 байт)** на файл, в интерфейсе обозначен как «10 МБ». Для обычной работы рекомендуется **до 5 МБ**: один прайс, каталог или описание услуги в одном материале. Текстовый PDF — не более 20 страниц; сканы удобнее загружать частями по 5–10 страниц, с чётким текстом. Изображения — до 12 млн пикселей, даже если файл занимает меньше 10 МБ.

Размер загрузки не равен нагрузке распознавания: сжатый скан на 1 МБ может требовать больше памяти, чем текстовый PDF на 10 МБ. Увеличение лимита до 25–50 МБ без отдельной очереди обработки и замеров на рабочем сервере не рекомендуется. После извлечения текста действует отдельный общий лимит базы знаний, поэтому большой документ может потребовать сокращения перед публикацией.

OCR использует установленные русскую и английскую модели. Казахский текст в текстовом PDF, DOCX, таблице и на сайте сохраняется как Unicode. Казахские буквы на сканах, а также числа и таблицы необходимо сверять с оригиналом.

Ссылка на соцсеть не равнозначна подключению аккаунта: можно импортировать только доступный текст конкретной публичной страницы. Закрытые профили, ленты, видео, страницы входа и содержимое, загружаемое только JavaScript, не поддерживаются. Для них можно загрузить файл или вставить текст вручную.

## Хранение и обновление

- Сохраняются отредактированный текст, категория, название файла или URL, дата импорта и проверки, признак OCR и SHA-256 извлечённого текста. Оригинал файла в базе знаний не хранится.
- SHA-256 относится к исходному извлечённому тексту; пользователь может отредактировать его при проверке.
- Ссылка может содержать параметры запроса; не используйте ссылки с паролями или персональными ключами доступа.
- Обновление страницы запускается вручную кнопкой «Проверить обновления страницы». Новая версия также требует проверки, сохранения и публикации.
- Старые материалы без метаданных источника продолжают работать. История опубликованных версий сохраняет новые метаданные в снимке анкеты.
- Дословные дубликаты блокируют публикацию. Предупреждения о разных ценах сравнивают похожие строки с суммами; это ограниченная подсказка, а не проверка всех смысловых противоречий.
- Текст материалов используется как факты компании. Общие правила ИИ и ограничения CRM имеют приоритет над инструкциями внутри файлов или страниц.

## Техническое устройство

`POST /api/v1/settings/ai-manager/knowledge-preview` возвращает предварительный просмотр без записи текста в действующую базу. Доступ проверяется по тем же правам, что настройка ИИ. Администратор сервиса использует явно выбранную компанию через `x-basqar-configuration-tenant`.

Бинарные файлы разбираются в Worker с отдельной V8-кучей и общим ограничением 90 секунд. Тяжёлое извлечение использует общий с импортом документов ограничитель: одна операция в одном процессе API; занятый процесс возвращает понятную ошибку 429. Временный каталог удаляется также при принудительном завершении Worker. Библиотеки Word, Excel и изображений загружаются только для соответствующего формата.

Лимит V8 не ограничивает всю память изображений и OCR/WASM — это отдельно оговорено в [документации Node.js](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html#new-workerfilename-options). На сервере с известным ограничением памяти перед созданием Worker проверяется свободный запас: 96 МиБ для TXT/MD, 256 МиБ для документов, 512 МиБ для изображений. Перед первым OCR дополнительно проверяется запас 320 МиБ. При его нехватке импорт возвращает 503 `knowledge_import_resources`, действующие знания не меняются, слот обработки освобождается. Это предварительная проверка, а не жёсткий предел общей памяти; её пороги требуют проверки на рабочем Linux-сервере с обычной нагрузкой CRM. На машине без известного ограничения контейнера проверка свободной памяти не применяется.

Загрузка сайтов использует HTTPS с проверкой публичности IP, закреплением проверенного DNS-адреса за соединением и повторной проверкой каждого перенаправления. Cookies и учетные данные клиента сайту не передаются. HTML не выполняется и не вставляется в интерфейс как разметка.

В журнал записывается событие `AI_KNOWLEDGE_IMPORT_PREVIEWED` с видом источника, объёмом текста, числом страниц и признаком OCR. Содержание материала и исходные файлы в это событие не попадают. Частота — до 12 попыток за минуту для пользователя в выбранной компании.

Изменений схемы БД и новых npm-зависимостей не требуется. Для выпуска нужны обновлённые API и веб-приложение. OCR использует уже имеющиеся зависимости обработки документов.

## Проверки

```sh
node scripts/test-api.mjs aiKnowledgeImport aiManagerSetup companyConfiguration securityMedia pdfOcrImage
npm run typecheck --workspace @creolab/api
npm run typecheck --workspace @creolab/web
npm run build --workspace @creolab/web
```

Проверки охватывают текстовые документы, реальный PNG с OCR, ограничения файлов, тайм-аут Worker, безопасность URL, права и изоляцию компаний, сохранение источников, обязательную проверку материала и применение через публикацию. Модель в тестах публикации подменена; это проверка механизма, не оценка качества ответов реальной модели на произвольных материалах.

### Локальные замеры 23.10.2026

Синтетические материалы, macOS arm64, Node.js 22.23.2; отдельный процесс и новый Worker на каждый файл. Память — максимальный наблюдавшийся RSS процесса с Worker, опрос каждые 10 мс. Полная CRM, другие запросы и задержка загрузки в эти измерения не входят. Скрипт и исходные результаты: `work/knowledge-import-check/benchmark.mts`, `work/knowledge-import-check/results.json`.
