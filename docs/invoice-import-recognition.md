# Распознавание счетов

Импорт PDF счёта извлекает наименование работы, количество, единицу, цену и итог. Для таблиц без заголовков наименования и количества используется расположение ячеек; многострочные названия объединяются. Количество × цена сверяется с суммой строки, итог позиций — с итогом документа. Неоднозначные или неполные данные остаются на проверку пользователя.

Назначение счёта (предоплата, остаток, дополнительный объём, полная оплата) определяется по тексту и доступно для исправления. Проценты и исходное уточнение сохраняются в `reviewedImport` события `document.import_pdf` вместе с позициями счёта. Детали возвращаются в `importDetails` при чтении счёта и документов сделки и показываются на карточке счёта. Если в тексте встречаются разные виды платежа, автоматический выбор не делается. Импорт не подтверждает фактическую оплату.

`GET /api/v1/documents/import-pdf/matches?buyerBin=…&contractNumber=…` подбирает компании по точному БИН / ИИН в текущей организации и возвращает их сделки. Единственная подходящая сделка выбирается автоматически; при указанном номере договора требуется совпадение номера. Несколько компаний с одним БИН / ИИН или несколько сделок требуют выбора пользователя.

При подтверждении заказчик сверяется с компанией выбранной сделки. Если компания у сделки отсутствует, привязывается найденная по БИН / ИИН карточка либо создаётся новая из проверенных реквизитов. Связь сохраняется одновременно у сделки и счёта. Реквизиты существующей компании и состав работ сделки не перезаписываются суммой частичного счёта.

Миграция базы не требуется. Для применения нужен выпуск обновлённых API и интерфейса. Ранее сохранённые неполные позиции автоматически не перераспознаются.

Проверки: `invoiceRecognition.test.ts` (табличные координаты, многострочные названия, суммы, назначение); `manualPdfImport.test.ts` (сохранение, подбор и привязка компаний, неоднозначность и изоляция организаций). В тестах используются вымышленные данные.
