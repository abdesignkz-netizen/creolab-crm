# Общая проверка BasQar — 14 октября 2026

Проверен локальный рабочий код, включая подготовленные изменения уведомлений BasQar Control. Деплой не выполнялся. Проверка интерфейса проведена на отдельной PGlite-базе: внешняя отправка сообщений и реальные платежи отключены. Рабочий сервер проверен только через публичные `/health` и `/ready`.

## Исправлено в этой проверке

1. **Пустой экран при ошибке раздела.** У приложения отсутствовал React Error Boundary: ошибка отрисовки или отклонённый lazy-import могла убрать весь интерфейс. Добавлен экран восстановления для разделов, сохраняющий оболочку и навигацию, и запасной обработчик на уровне приложения. Пользователь видит кнопку перезагрузки и переход на главную. Технические сведения ошибки не выводятся пользователю. Автоматического повтора платежа или отправки сообщения нет. Текст переведён на казахский и английский.
2. **Неоднозначное создание документов.** Общая кнопка «Создать документ» открывала исключительно шаблоны договоров. Теперь она предлагает договор, счёт, АВР и ЭСФ, используя существующие редакторы и проверки доступа. В шаблонах есть возврат к выбору типа.

Исправления Control из предыдущей проверки сохранены: объединение очереди, соблюдение интервала всеми автоматическими отправками, проверка тихих часов, защита несохранённых настроек и мобильная панель сохранения.

## Остающиеся недостатки

- **Зависимости:** итоговый `npm audit --omit=dev` содержит 29 записей: 20 high, 9 moderate, 0 critical (было 42). В отдельно установленном наборе для API/сайта — 0 вместо 6. Остаток относится к мобильному дереву Expo/React Native и его инструментам; это записи пакетов, а не 29 подтверждённых ошибок работающего сайта. Подробности и границы проверки: [обновление зависимостей](dependency-security-2026-10-14.md).
- **Первая загрузка:** после оптимизации начальный JS около 1 053 kB, gzip около 269 kB (было 1 219 / 315 kB). Основная оставшаяся составляющая — общий словарь локализации; предупреждение Vite о размере чанка сохраняется. Время загрузки на реальном устройстве и слабой сети не измерялось.
- **Внешние сценарии:** успешное списание картой, реальная доставка WhatsApp/Telegram/Instagram, подписание ЭЦП и качество ответов реального ИИ в эту проверку не входили. Автоматические тесты используют изолированные данные и заменяют внешних провайдеров.
- **Мобильное приложение:** проверены TypeScript, адаптивный веб-интерфейс и экспорт JavaScript/Hermes для Android/iOS. Нативные APK/IPA и поведение на устройстве не проверены.

## Продолжение: зависимости и первая загрузка

1. **PostCSS:** зависимость Expo Metro обновлена с 8.4.49 до 8.5.30 через ограниченный override для `@expo/metro-config`. Веб-сборка и экспорт мобильного JS проходят. Зависимости остальных основных версий сохранены. В частности, обновление React Navigation выявило неявную зависимость старого Expo Router от `query-string`; несовместимое обновление не вошло в итоговые изменения.
2. **Серверный образ:** `apps/api/Dockerfile` устанавливает только API, web, db, contracts и integrations, явно генерирует Prisma Client, собирает сайт и удаляет dev-зависимости с тем же списком пакетов. Чистая установка в отдельную папку подтвердила отсутствие Expo и React Native. Установлено 484 пакета вместо полного дерева монорепозитория; это не измерение размера Docker-образа. Проверены генерация Prisma, веб-сборка и серверные тесты на сокращённой установке. Полная Docker-сборка не выполнена: Docker на этом компьютере отсутствует, Linux-образ и этап сборки speech-модели требуют отдельной проверки при деплое.
3. **Первая загрузка:** пакет contracts помечен `sideEffects: false`: его модули экспортируют значения и функции, без обязательных внешних эффектов при импорте. Сборщик исключает неиспользуемые схемы из начального набора и загружает нужные вместе с соответствующими страницами. Серверные импорты и валидация сохраняются. Снижение начального JS — 166 kB, gzip — 46 kB, примерно 14%.
4. **Контроль регрессий:** production-сборка создаёт Vite manifest и запускает `scripts/check-web-bundle.mjs`. Проверяется весь граф статических JS-импортов, включая общие чанки: не более 1 100 kB исходного минифицированного JS и 285 kB gzip. Простое перемещение кода в синхронный vendor-чанк не обходит лимит. Это бюджет размера, а не измерение скорости или гарантия производительности.
