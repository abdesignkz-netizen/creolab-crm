# Подключения компании: Telegram, Google, Meta и TikTok

Реализация находится в разделе **«Интеграции» компании**. Подключением управляют сотрудники с правом управления интеграциями; действуют ограничения тарифа. Каталог платформы описывает возможности, а авторизация аккаунтов выполняется внутри выбранной компании.

Наличие программного модуля не означает, что внешний аккаунт уже подключён. Нужны действительные доступы, настройки приложения поставщика и проверка реальной доставки. Автоматические тесты заменяют внешние API контролируемыми ответами; действительные аккаунты ими не проверяются.

## Что реализовано

| Подключение | Работа в CRM | Границы текущей реализации |
|---|---|---|
| Telegram-бот компании | Личные входящие сообщения, поддерживаемые вложения, текстовые ответы и файлы из диалогов | Клиент первым пишет боту. Группы игнорируются. Автоматические ответы AI не подключены. Сообщение само по себе не создаёт заявку |
| Google Calendar | Создание и обновление событий по договорённостям CRM, удаление отменённых событий | Передача из CRM в Google. События, созданные в Google, не импортируются. Один выбранный календарь на компанию |
| Instagram Direct | Входящие сообщения профессионального аккаунта, текстовые ответы сотрудников | Ответ до 1000 символов в течение 24 часов после сообщения клиента. Вложения представлены отметкой, оригиналы открываются в Instagram. AI и отправка вложений не подключены |
| Meta Lead Forms | Заявки рекламных форм с телефоном; очередь уточнения для обращений без телефона | Требуются разрешения Meta на чтение лидов. Принимаются новые уведомления; историческая выгрузка не выполняется |
| Google Forms | Новые ответы формы, автоматическое определение и ручное сопоставление имени, телефона, email и сообщения | Одна выбранная форма. Поддерживаются обычные вопросы; вопросы в таблицах и загрузка файлов не импортируются как отдельные вложения |
| TikTok Leads | Новые заявки выбранной Instant Form, проверка доступа, подписка на доставку, повторная проверка и отключение | TikTok for Business, рекламный аккаунт и конкретная форма. Лиды Direct Message и историческая выгрузка не подключены |
| Входящая почта Gmail | Новые письма Inbox и поддерживаемые вложения в диалогах | Один ящик. Только приём: отправка ответов, удаление писем и изменение их прочитанности не выполняются. IMAP, Outlook и другие почтовые службы не реализованы |

Переписки новых каналов открываются в режиме сотрудника. Неназначенные диалоги доступны руководителю, который назначает ответственного. Заявки рекламных форм проходят существующую обработку заявок CRM. Если телефон отсутствует или некорректен, сохраняются исходные поля и создаётся задача уточнения — номер не придумывается.

## Общие условия эксплуатации

1. Сервер CRM доступен по постоянному публичному HTTPS-адресу. `API_BASE_URL` содержит внешний адрес API, `APP_BASE_URL` — адрес кабинета. Эти адреса должны соответствовать настройкам развертывания.
2. Постоянный ключ шифрования CRM настроен и сохранён администратором. Учётные данные поставщиков записываются зашифрованными в существующую таблицу `Credential`; API списков не возвращает токены и секреты.
3. Для Google работают фоновые задания API или worker. Проверка запускается примерно раз в минуту; большой объём данных и задержки поставщика увеличивают фактический интервал. Есть кнопка ручной синхронизации.
4. Приём сообщений Telegram, Meta и TikTok требует доступа поставщика к публичным callback-адресам. Изменение домена требует перенастройки этих адресов.
5. Ограничения вложений CRM: до 16 МБ на файл и до пяти исходящих файлов. Gmail импортирует до пяти поддерживаемых вложений письма. Недоступные или неподдерживаемые вложения отмечаются в тексте и остаются у поставщика.

Миграции схемы базы для этих подключений не требуются. Рабочие `.env` и данные компаний при разработке не изменяются.

## Telegram

1. Создать отдельного бота через `@BotFather` командой `/newbot`.
2. Ввести токен в блоке «Telegram-бот компании». CRM проверит бота и зарегистрирует адрес доставки.
3. Из другого Telegram-аккаунта написать боту, открыть диалог в CRM и ответить из него.
4. Проверить текст и вложение в обе стороны, затем назначить ответственного сотрудника.

CRM отказывается заменять адрес доставки бота, обслуживаемого другой системой. Повторное подключение уже действующего бота обновляет доступ, сохраняя приём сообщений. Можно подключить несколько отдельных ботов; каждый отображается в списке. Личные Telegram-уведомления сотрудников остаются отдельной функцией.

Входящие запросы проверяются по секретному заголовку Telegram. Повторная доставка не создаёт второе сообщение. При неизвестном результате исходящей отправки CRM сохраняет этот статус и не отправляет повторно по тому же ключу: сначала следует проверить переписку.

Официальный справочник: [Telegram Bot API](https://core.telegram.org/bots/api).

## Google: общая авторизация

Администратор сервиса создаёт OAuth-клиент типа **Web application** в Google Cloud, включает Calendar API, Forms API и Gmail API и задаёт `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` в окружении сервера. Точный redirect URI:

```text
https://<внешний-адрес-API>/api/v1/integrations/google/callback
```

Нужно настроить экран согласия и доступ пользователей к приложению. Требования Google к проверке приложения и срокам доступа зависят от режима публикации и используемых разрешений. Для Gmail используется разрешение чтения почты, поэтому подготовку приложения нужно выполнить до подключения внешних компаний.

Пользователь выбирает тип подключения и проходит вход в Google. Подтверждение привязано к текущей сессии и компании, действует десять минут и принимается один раз. При отсутствии необходимых разрешений или постоянного доступа подключение не публикуется. Access token обновляется через refresh token.

| Тип | Разрешения |
|---|---|
| Календарь | `calendar.events`, `calendar.calendarlist.readonly` |
| Формы | `forms.body.readonly`, `forms.responses.readonly` |
| Почта | `gmail.readonly` |

Используется полный префикс разрешений `https://www.googleapis.com/auth/`.

Для каждого из трёх типов активно одно подключение на компанию. Подтверждённое подключение другого ресурса отключает предыдущее, сохраняя историю. Повторная авторизация того же ресурса сохраняет позицию синхронизации. Письма разных ящиков разделены, даже если поставщик вернул одинаковые идентификаторы сообщений.

### Календарь

Указать ID календаря или `primary`. Аккаунту необходимо право изменения событий. При первой синхронизации обрабатываются договорённости CRM с датой; далее — изменённые записи. Повторная синхронизация использует тот же идентификатор события, перенос обновляет существующее событие. Завершённые встречи сохраняются; отменённые удаляются из выбранного календаря.

Созданные вручную события Google не затрагиваются. При отключении или выборе другого календаря ранее созданные события в старом календаре остаются. Старый адаптер через переменные окружения не вызывается одновременно с активным OAuth-подключением компании.

### Формы

Ввести ID из адреса **редактора** Google Forms. После авторизации открыть «Сопоставить поля» и выбрать нужные вопросы, особенно если они имеют нестандартные названия. По умолчанию поля определяются по названиям.

Импорт начинается с первого подключения формы. Повторные ответы определяются по ID формы и ответа. Последующее редактирование уже импортированного ответа не перезаписывает заявку. Пятиминутное перекрытие периода опроса снижает риск пропуска задержанных ответов; оно не создаёт дубликаты.

### Входящая почта

Подключить Google-аккаунт нужного ящика и отправить ему новое письмо. Читается Inbox, без Spam и Trash. Письма до первого подключения не импортируются. Проверка использует перекрытие суток для задержанной индексации; письма, попавшие во входящие намного позже исходной даты, могут потребовать отдельного импорта, который сейчас не реализован.

В CRM сохраняется текстовая часть, а при её отсутствии — превью. HTML письма не исполняется. Поддерживаемые вложения сохраняются в хранилище CRM. Кнопка отправки в почтовых диалогах недоступна; ответ отправляется из Gmail.

Документация: [OAuth для серверных приложений](https://developers.google.com/identity/protocols/oauth2/web-server), [события Calendar](https://developers.google.com/workspace/calendar/api/v3/reference/events), [ответы Forms](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses/list), [сообщения Gmail](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list).

## Meta: Instagram Direct и Lead Forms

Используется подключение через **Facebook Page Access Token**, а не отдельный Instagram Login. Для Instagram необходим профессиональный аккаунт, связанный со страницей Facebook. В блоке Meta вводятся App ID, Page ID, Page Access Token, App Secret и поддерживаемая версия Graph API приложения. CRM проверяет принадлежность токена приложению и странице.

После настройки CRM показывает Callback URL и Verify Token. В приложении Meta необходимо подтвердить callback и выбрать:

- Для Instagram — объект Instagram и поле `messages`.
- Для форм — объект Page и поле `leadgen`.

Затем нажать **«Проверить и включить»**. Без подтверждения callback канал не активируется. Существующие поля подписки приложения на странице сохраняются; включение форм не снимает подписку на сообщения. Один app/object не подключается ко второму аккаунту с заменой действующего callback: для него требуется отдельное приложение. Instagram и формы могут использовать одно приложение, поскольку это разные объекты.

Разрешения и доступ приложения должны соответствовать выбранному продукту: чтение лидов, управление подпиской страницы и, для Instagram, доступ к профессиональному аккаунту и сообщениям. Для клиентов вне ролей приложения может потребоваться Advanced Access и одобрение Meta. Нужно проверить доставку сообщения/заявки от реального внешнего пользователя после настройки.

POST-уведомления проверяются по HMAC-подписи `X-Hub-Signature-256` и принадлежности получателя. Повторная доставка не создаёт дубликаты. Отключение прекращает приём в CRM и удаляет сохранённый доступ. Подписка приложения на стороне Meta автоматически не удаляется, поскольку она может обслуживать второй канал; при необходимости её удаляет администратор приложения.

Источники: [Meta — Webhooks for Pages](https://developers.facebook.com/docs/graph-api/webhooks/getting-started/webhooks-for-pages/), [проверка токена](https://developers.facebook.com/docs/graph-api/reference/debug_token/), [официальная коллекция Instagram](https://www.postman.com/meta/instagram/overview).

## TikTok Leads

Нужно приложение **TikTok for Business** с доступом к Lead Generation и права администратора рекламного аккаунта. В CRM указываются App ID, App Secret, Access Token, Advertiser ID и Page ID конкретной Instant Form.

CRM сначала запрашивает поля формы, чтобы подтвердить доступ, затем создаёт подписку `LEAD` с `lead_source=INSTANT_FORM`. Если связь оборвалась после создания подписки, кнопка проверки находит её по адресу доставки, вместо создания второй. Отключение удаляет только подписки с адресом этого подключения CRM; чужие подписки не меняются. При недоступности TikTok операция сообщает об ошибке, после восстановления связи её нужно повторить.

Уведомление содержит поля заявки. Принимаются только выбранные рекламный аккаунт и форма. Длинные числовые ID читаются без потери точности. В качестве защиты доставки используется отдельный случайный секрет в callback-адресе; в открытых данных подключения этот адрес не выдаётся, в базе сохраняются хеш ключа и зашифрованные реквизиты.

Это API Business Subscriptions. Заголовок подписи другого продукта TikTok for Developers к нему не приписывается. **На reverse proxy следует исключить полный путь `/public/integrations/tiktok/…` из журналов доступа или маскировать последний сегмент**, поскольку он содержит секрет доставки. CRM не пишет этот адрес и секреты API в свои сообщения об ошибках. Не публиковать и не пересылать callback-адрес.

Официальные документы: [доставка событий](https://business-api.tiktok.com/portal/docs?id=1810521739537409), [создание подписки](https://business-api.tiktok.com/portal/docs?id=1739092028876801), [проверка подписок](https://business-api.tiktok.com/portal/docs?id=1739093832125442), [отключение](https://business-api.tiktok.com/portal/docs?id=1739094758789122).

## Проверка перед использованием компанией

Для каждого подключённого аккаунта выполнить одну настоящую доставку и проверить её в CRM: текст, нужную компанию, источник, отсутствие дубликата и назначение ответственного. Для Telegram/Instagram отдельно проверить ответ сотрудника. Для календаря проверить перенос и отмену. Для форм проверить ответ без телефона, для почты — письмо с вложением.

Проверки кода находятся в `telegramCompany.test.ts`, `googleConnections.test.ts`, `metaConnections.test.ts`, `tiktokConnections.test.ts`. Они используют временные базы и подменённые ответы внешних API. Дополнительно запускаются общий набор тестов, проверка типов и сборка веб-интерфейса. Эти проверки не заменяют проверку разрешений и доставки настоящего аккаунта.
