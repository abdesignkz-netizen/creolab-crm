# Уведомления

Центр уведомлений в API: `GET /api/v1/notifications`. События заявки и «нет телефона» создаются на сервере сразу.

## Каналы

| Канал | Статус |
| --- | --- |
| Внутри CRM | Реализован |
| Native push Expo | Контракт устройств есть (`DeviceInstallation`). Не проверен: нет development build и APNs/FCM. |
| Web Push | Реализован при наличии VAPID и активной подписки браузера. Доставка захватывается одним обработчиком; сетевой запрос ограничен по времени. Фактическая настройка рабочего окружения проверяется отдельно. |
| Telegram сотрудника | Реализованы привязка через одноразовый токен, отзыв привязки, тест и очередь доставки. Требует настроенного отдельного бота и включённых личных уведомлений. Telegram-бот компании принимает обращения клиентов отдельно. |
| WhatsApp руководителя / BasQar Control | Реализованы правила событий, тихие часы, интервалы и объединение ожидающих уведомлений. Нужны разрешённый сотрудник, включённое правило и поддерживаемое подключение; см. `control-whatsapp-notifications.md`. |

Пока внешний канал не настроен, событие всё равно сохраняется в CRM.

## Дедуп и эскалации

Ключ: `tenant + episodeKey + recipientMembershipId`. Повтор заявки обновляет то же уведомление.

Новые доставки внутри CRM и Web Push имеют постоянный ключ на пару «уведомление + канал», чтобы параллельные обработчики не создавали дубли. Telegram использует такую же защиту отдельной очереди.

Напоминания о договорённостях хранятся в `ScheduledAction`: обычно за сутки и час, для встреч/звонков также за 30 минут. Создаются только будущие напоминания. Они могут восстановиться после остановки обработчика, сохраняя ключ уведомления. Универсальная эскалация любого события через 5/15 минут не реализована и не должна обозначаться как работающая функция.

Ошибка или прерывание запланированной отправки задачи создаёт событие `task.send_failed`: ответственному в CRM и, если включено, в личный Telegram; руководителю — по правилам Control категории «Задачи». Повтор одного события не создаёт новое уведомление. Неизвестный результат внешней отправки требует сверки: система не отправляет сообщение повторно вслепую.

Чтение уведомления не закрывает задачу.

## Тест себе

Личный Telegram: `POST /api/v1/telegram/test`. WhatsApp Control: `POST /api/v1/workspace/control/notifications/:id/test`. Эти действия действительно отправляют тестовое уведомление при наличии подключения. Запись внутри CRM можно проверить в центре уведомлений.

## Ограничения

- Expo Go не считается доказательством push.
- iOS Web Push только у установленного PWA 16.4+.
- Секреты и полная переписка в push не кладутся.
