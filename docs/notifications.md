# Уведомления

Центр уведомлений в API: `GET /api/v1/notifications`. События заявки и «нет телефона» создаются на сервере сразу.

## Каналы

| Канал | Статус |
| --- | --- |
| Внутри CRM | Реализован |
| Native push Expo | Контракт устройств есть (`DeviceInstallation`). Не проверен: нет development build и APNs/FCM. |
| Web Push | Модель подписки есть. VAPID не задан — канал выключен. |
| Telegram сотрудника | Привязка через одноразовый токен запланирована. Текущий Telegram бота (`/api/lead`) — отдельный канал заявок сайта, не путать. |

Пока внешний канал не настроен, событие всё равно сохраняется в CRM.

## Дедуп и эскалации

Ключ: `tenant + episodeKey + recipientMembershipId`. Повтор заявки обновляет то же уведомление.

Напоминание high-priority через 5 рабочих минут и эскалация через 15 — пишутся в `ScheduledAction`. Worker обрабатывает их из PostgreSQL, не из Redis.

Чтение уведомления не закрывает задачу.

## Тест себе

`POST /api/v1/notifications` тест-доставка на своё устройство появится после credentials. Сейчас проверка — появление записи в центре после формы.

## Ограничения

- Expo Go не считается доказательством push.
- iOS Web Push только у установленного PWA 16.4+.
- Секреты и полная переписка в push не кладутся.
