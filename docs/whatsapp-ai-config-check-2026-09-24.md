# Проверка промпта и базы знаний WhatsApp AI-менеджера

Обновление: обнаруженное отсутствие материалов и обрезание исправлены; промпт и полная база опубликованы на рабочем сервере. Итоги — в `whatsapp-ai-publication-2026-09-24.md`. Ниже сохранены результаты первоначальной проверки до исправления.

Дата: 24.09.2026. Проверен рабочий BasQar `https://crm.creolab.kz`, компания CREOLAB, через штатные API владельца и администратора сервиса. Настройки не изменялись; сообщения клиентам не отправлялись.

## Вывод

Связь CRM с WhatsApp AI-сервисом работает, но промпт и база знаний компании в рабочей админке отсутствуют. Считать ранее настроенную цепочку «админка → опубликованная конфигурация → ответы WhatsApp» исправной сейчас нельзя. Какие встроенные инструкции использует внешний бот, этой проверкой не установлено.

## Проверка кода

1. Публикация промпта сохраняет `AIConfiguration.systemPrompt` и вызывает регистрацию интеграции. База знаний хранится отдельно в `KnowledgeDocument`; в рабочий контекст попадают опубликованные документы текущей компании.
2. Вызов регистрации передаёт промпт, базу знаний и настройки модели внешнему AI Manager. Статус «Активен в WhatsApp» вычисляется по локальным отпечаткам после регистрации; проверки реального ответа бота или чтения его применённой конфигурации нет. Наличие строки интеграции также принимается за подключение при вычислении этого статуса.
3. В `apps/api/src/services/aiManagerRegistration.ts` база знаний обрезается через `.slice(0, 20000)`. Локальная сохранённая база CreoLab содержит **28 176 символов**, поэтому полностью в такой запрос не помещается. Отпечаток при этом рассчитывается по исходным документам. CRM-предпросмотр использует иной предел — 12 000 символов в `buildTenantAiSystemPreamble`; он не эквивалентен ответу внешнего WhatsApp-бота.
4. Регистрация повторно читает текущую конфигурацию при записи отпечатков, поэтому при параллельном редактировании они могут описывать уже другую версию, чем отправленный запрос.
5. Материалы CreoLab в репозитории загружаются через `applyCreolabAiManagerDefaults` при seed. Обычный запуск API эту операцию не выполняет. Наличие файлов в репозитории не означает, что они опубликованы в рабочей БД. Фактическая причина отсутствия материалов в production по доступным данным не установлена.

## Сохранённые материалы

- `packages/db/assets/creolab-ai/system_prompt.txt` — 22 942 символа.
- `packages/db/assets/creolab-ai/knowledge_base.txt` — 28 176 символов.

В локальной базе знаний указана версия `1.5-draft` и отмечены нерешённые вопросы по прайсу. Это материал для восстановления и проверки актуальности; он не был автоматически опубликован в production.

## Тесты

`npm test --workspace=@creolab/api -- aiManagerActivation aiManagerSaaS` — успешно: 3 теста статусов и 7 тестов SaaS-интеграции, 2/2 файла. Проверяются публикация, черновики, изоляция компаний и передача данных через mock внешнего сервиса. Это не проверка ответа действующего WhatsApp-бота.

## Что нужно для восстановления и окончательной проверки

1. Проверить актуальность сохранённых промпта и коммерческих данных.
2. Устранить тихое обрезание базы знаний и привести проверку применённой версии к реально отправленному содержимому.
3. Опубликовать материалы CREOLAB в рабочей админке и синхронизировать их с ботом.
4. Проверить сохранность конфигурации внешнего AI Manager и выполнить контрольный ответ на тестовом диалоге по конкретному факту из базы. Отправка в WhatsApp в текущую проверку не входила.
