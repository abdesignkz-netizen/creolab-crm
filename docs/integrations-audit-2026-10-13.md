# Проверка интеграций — 13 октября 2026

Проверены все 13 карточек раздела «Интеграции» в рабочем кабинете CREOLAB на bsqr.kz и код подключения. Исправления подготовлены локально, деплой не выполнялся.

## Продолжение: личные Telegram-уведомления

После аудита реализованы привязка по Start, персональная очередь доставки, настройки и отключение. Описание настройки и проверок: [employee-telegram-notifications.md](employee-telegram-notifications.md). Ниже сохранены результаты исходного аудита; отметка «реализация отсутствует» относится к состоянию до этой доработки. Production требует отдельного настроенного бота и деплоя.

## Исправлено

- Green API больше не показывает успешное подключение, когда сервер сохранил настройки, но не подтвердил доступность.
- Ошибка загрузки статуса больше не сопровождается сообщением об успешной проверке. Кнопка проверки блокируется на время запроса; более старые ответы не заменяют новые данные.
- Ошибка проверки Green API отображается предупреждающим статусом, а не зелёным значком только из-за наличия настроек.
- Неуспешная проверка Telegram и неполная проверка формы/Webhook не показываются как зелёное подтверждение успеха.
- Ошибки создания ссылки для Telegram сотрудника перехватываются и показываются пользователю; повторные нажатия блокируются до завершения запроса.
- Пустые ответы со списком подключений Google или без подключения ЭСФ не оставляют вечную «Загрузку».
- При переподключении Google сохраняется ID выбранного календаря или формы. Раньше поле календаря начиналось с `primary`, а ID формы оставался пустым, хотя название подключённого ресурса уже было известно. API теперь возвращает ID отдельно от отображаемого названия; добавлен регрессионный тест.
- Google OAuth возвращает пользователя в интерфейс при отмене входа, истечении подтверждения, недостаточных разрешениях и сбоях провайдера. Технический JSON больше не показывается. Успех открывает нужную карточку; одноразовый параметр результата удаляется из URL без потери якоря карточки. Подробности провайдера и коды авторизации не включаются в адрес возврата.
- Инструкции Google уточнены: ID календаря или формы вводится до начала авторизации.
- Ошибки обновления списка TikTok после действия больше не скрываются.
- Выявлена незавершённая реализация **личных уведомлений сотрудника в Telegram**: есть таблица привязок и ранее выдавалась ссылка Start, но обработчика подтверждения и доставки уведомлений нет. Наличие переменных окружения не делает эту функцию рабочей. Она обозначена «В разработке»; API больше не создаёт бесполезные токены привязки. Это не меняет интеграцию Telegram-бота компании для клиентских диалогов. Старые записи привязок не удаляются.

## Проверки

- Первоначально прошли 140 сценариев в 16 уникальных серверных тестовых файлах. После продолжения проверки прошли 52 сценария в пяти затронутых файлах (`googleConnections`, `integrationsFoundation`, `accessControl`, `telegramCompany`, `tiktokConnections`), включая новые сценарии ошибок OAuth и недоступных личных Telegram-уведомлений. В тестах используются изолированные PGlite-базы и имитации внешних провайдеров.
- Проверялись OAuth/state, токены и подписи событий, разграничение компаний, повторная доставка без дубликатов, импорт заявок и сообщений, отключение с сохранением истории, сайт-чат, WhatsApp QR в фоне и авторизация ЭСФ.
- После последних изменений повторно прошёл весь `googleConnections` (14 сценариев). Отказ в доступе, истечение state, сбой провайдера и возврат без сессии не создают новые подключения и не заменяют существующие.
- Проверка типов API и веб-приложения прошла.
- Веб-сборка прошла. Сохранилось предупреждение о чанках больше 500 kB; ошибок сборки нет.
- В локальном браузере подтверждено: неподключённые интеграции имеют конечный статус, проверка неподключённого Green API показывает инструкцию по настройке, а не сообщение об успехе. В журнале локальной вкладки ошибок не обнаружено.
- Проверен полный локальный переход через Google callback с недействительным state: API возвращает в «Интеграции», интерфейс показывает понятное сообщение и удаляет одноразовый параметр из URL. Отдельно проверены сообщение об отмене входа и недоступность Telegram-уведомлений сотрудника.
- `git diff --check` прошёл.
