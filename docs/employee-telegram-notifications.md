# Личные Telegram-уведомления сотрудников

Реализовано: 13.10.2026. Это общий служебный бот BasQar, отдельный от Telegram-ботов компаний для общения с клиентами.

## Настройка сервера

1. Создать отдельного бота в BotFather. Не использовать токен клиентского бота компании.
2. В защищённых переменных окружения API указать:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_BOT_USERNAME` — его username, с `@` или без;
   - `TELEGRAM_WEBHOOK_SECRET` — случайная строка 32–256 символов (`A-Z`, `a-z`, `0-9`, `_`, `-`);
   - `API_BASE_URL` — публичный HTTPS-адрес API; при необходимости отдельный адрес задаётся через `TELEGRAM_WEBHOOK_BASE_URL`;
   - `APP_BASE_URL` — адрес кабинета для кнопки в уведомлении.
3. Собрать Prisma Client и развернуть API и web. При старте применяются добавочные столбцы TelegramBinding.botId, NotificationDelivery.nextAttemptAt/claimedAt и индекс очереди. Старые неподтверждённые привязки не считаются подключёнными.
4. Открыть «Настройки → Уведомления → Telegram сотрудника» и нажать «Подключить Telegram». Сервер сверяет токен и username через getMe, проверяет, что бот не используется другим подключением, и регистрирует webhook с секретным заголовком.
5. Открыть полученную ссылку, нажать «Запустить» в личном чате с ботом. В кабинете статус сменится на «Подключено». Нажать «Проверить доставку» и убедиться, что уведомление действительно пришло в Telegram.

Webhook: `POST /public/telegram/employee-notifications`. Доступен без CRM-сессии, но требует верного `X-Telegram-Bot-Api-Secret-Token`. Не использовать GET URL с токеном для ручной установки webhook. Секреты не попадают в ответы API и журналы ошибок.

После смены webhook-секрета выполнить «Проверить доставку»: это заново сверит бота и зарегистрирует актуальный webhook. При замене самого бота сотрудники должны подключить нового; сообщения из старой очереди новому боту не отправляются.

## Поведение

- Доступно каждому активному сотруднику, включая менеджеров, без права управления интеграциями компании.
- Одноразовая ссылка действует 10 минут; новая ссылка отменяет предыдущую. В БД только SHA-256, открытый токен возвращается только в личной ссылке.
- Привязка относится к пользователю BasQar. Один личный чат не может принадлежать двум пользователям. При подключении уведомления включаются только для текущей компании. Для других компаний сотрудник включает их отдельно.
- Категории событий учитываются до постановки в очередь и ещё раз перед отправкой. Используются существующие рабочие уведомления BasQar, включая заявки, передачу диалога, напоминания и подтверждение задач, подписанные договоры, ответы поддержки и события подписки.
- Тихие часы откладывают Telegram-доставку до их окончания. Часовой пояс — настройка пользователя, по умолчанию Asia/Almaty. Одинаковое время начала и конца означает отсутствие тихого интервала.
- Прочитанные и разрешённые уведомления, отключённые категории, отключённый канал и удалённый доступ сотрудника отменяют ожидающую доставку.
- Уведомление содержит компанию и категорию события; клиентская переписка, имена клиентов и телефоны в Telegram не передаются. Подробности доступны после входа в кабинет.
- «Отключить Telegram» и команда `/stop` отменяют привязку во всех компаниях. Блокировка бота также отключает её. Уже начатую сетевую отправку отменить невозможно.
- Доставка выполняется фоновым процессом API каждые 5 секунд и не зависит от открытого браузера. Сервер должен работать постоянно. Очередь сохраняется в БД и переживает перезапуск.
- На один рабочий эпизод создаётся одна Telegram-доставка; конкурирующие процессы атомарно забирают запись очереди.
- Telegram 429 повторяется после retry_after, не более пяти попыток. При таймауте, 5xx или перезапуске во время отправки результат обозначается как неизвестный и автоматического повтора нет: sendMessage не предоставляет ключ идемпотентности. В настройках виден фактический результат последней доставки.
- Проверочное уведомление учитывает тихие часы; повторное нажатие в пределах минуты не создаёт дубль.

## Проверка

`node scripts/test-api.mjs employeeTelegram accessControl integrationsFoundation telegramCompany backgroundReliability`

Результат: 52 серверных теста (включая 19 новых сценариев личного Telegram) и 34 web-теста прошли. Typecheck API/web и сборка web успешны; сборка сохраняет прежнее предупреждение о крупных chunks. В браузере проверены создание ссылки, автоматическое подтверждение, очередь → доставка и отключение; на ширине 390 px горизонтальной прокрутки нет.

Тесты используют отдельную PGlite БД и имитацию Telegram API; настоящие сообщения не отправляются. Проверка на реальном Telegram требует настроенного служебного бота и подтверждения сотрудником через Start. Локальная реализация сама по себе не означает, что бот уже настроен в production.

Официальный протокол: [deep linking](https://core.telegram.org/bots/features#deep-linking), [setWebhook](https://core.telegram.org/bots/api#setwebhook).
